# Codex 작업지시서: MediaPipe 얼굴 랜드마크 출력

## 1. 목표

첨부 예시처럼 얼굴 이미지에 MediaPipe Face Mesh의 랜드마크 점, 연결선, 번호를 표시하고 결과 이미지를 저장하는 Python 프로그램을 구현한다.

완료 결과물:

- `face_landmark.py`: 실행 프로그램
- `requirements.txt`: 최소 의존성 목록
- `face_landmark_result.jpg`: 실행 후 생성되는 결과 이미지

## 2. 작업 원칙

- 작업 전 현재 폴더의 관련 파일만 확인한다. 전체 디렉터리를 불필요하게 탐색하지 않는다.
- 기존 파일이 있으면 먼저 내용을 읽고 재사용한다.
- 요구사항과 직접 관련 없는 파일은 수정하지 않는다.
- 코드는 짧고 읽기 쉽게 작성하며 불필요한 클래스·프레임워크·설명을 추가하지 않는다.
- 같은 오류가 반복되면 원인을 분석한 뒤 수정한다. 동일 명령을 무의미하게 반복하지 않는다.
- 사용자의 추가 확인이 없어도 안전한 범위에서 구현, 실행, 검증까지 완료한다.
- 입력 이미지와 기존 사용자 파일은 삭제하거나 변경하지 않는다.

## 3. 입력과 출력

### 입력

- 기본 입력 파일: `face.jpg`
- 명령행에서 다른 이미지 경로를 지정할 수 있게 한다.

```bash
python face_landmark.py face.jpg
```

### 출력

- 기본 출력 파일: `face_landmark_result.jpg`
- 출력 파일이 이미 존재하면 정상적으로 덮어쓴다.
- 원본 이미지에는 덮어쓰지 않는다.
- 성공 시 출력 파일의 경로와 검출된 랜드마크 수를 표시한다.

## 4. 구현 요구사항

1. Python 3.10 이상을 기준으로 작성한다.
2. `opencv-python`과 `mediapipe`를 사용한다.
3. 이미지를 OpenCV로 읽고 BGR에서 RGB로 변환한다.
4. MediaPipe Face Mesh 또는 설치 버전에서 지원되는 Face Landmarker를 사용한다.
5. 한 개의 얼굴을 검출한다.
6. 얼굴 전체 테셀레이션 연결선을 표시한다.
7. 각 랜드마크 위치에 점과 번호를 표시한다.
8. 작은 이미지에서도 번호가 보이도록 글자 크기와 두께를 이미지 크기에 맞춰 조절한다.
9. 결과를 이미지 파일로 저장한다.
10. GUI 창은 선택 기능으로 둔다. 기본 실행은 창을 띄우지 않아 서버·Codex 환경에서도 종료되어야 한다.
11. `--show` 옵션이 있을 때만 결과 창을 표시한다.
12. 경로 처리는 `pathlib.Path`를 사용한다.

권장 실행 형식:

```bash
python face_landmark.py [INPUT] [-o OUTPUT] [--show]
```

## 5. 오류 처리

다음 상황에서는 Python traceback을 그대로 노출하지 말고 이해하기 쉬운 오류 메시지와 0이 아닌 종료 코드를 반환한다.

| 상황 | 처리 |
|---|---|
| 입력 파일 없음 | 파일 경로를 포함해 안내하고 종료 |
| 지원하지 않거나 손상된 이미지 | 이미지를 읽을 수 없다고 안내하고 종료 |
| MediaPipe/OpenCV 미설치 | 설치 명령을 안내하고 종료 |
| 얼굴 미검출 | 정면·밝기·얼굴 크기를 확인하라고 안내하고 종료 |
| 결과 저장 실패 | 출력 경로와 권한을 확인하라고 안내하고 종료 |
| 입력·출력 경로가 동일 | 원본 보호를 위해 실행 중단 |
| GUI 미지원 환경에서 `--show` 사용 | 저장 성공 여부는 유지하고 창 표시 실패만 안내 |

오류 메시지에 인증키, 환경 변수, 사용자 개인정보를 출력하지 않는다.

## 6. 버전 호환성

- 먼저 설치된 Python과 패키지 버전을 확인한다.
- 현재 MediaPipe API에서 `mp.solutions.face_mesh`가 제공되면 이를 우선 사용한다.
- 제공되지 않으면 최신 Tasks API로 전환하되, 모델 파일이 필요한 경우 명확한 다운로드 절차를 README에 기록한다.
- 버전 문제를 숨기기 위해 임의로 광범위한 패키지 업그레이드를 하지 않는다.
- `requirements.txt`에는 실제 사용한 최소 패키지만 기록한다.

## 7. 토큰·작업 효율화

- 먼저 `README.md`, 기존 Python 파일, 의존성 파일만 확인한다.
- 파일 검색은 `rg --files`와 `rg`를 우선 사용한다.
- 긴 로그는 전부 출력하지 말고 오류의 핵심 부분만 확인한다.
- 코드 전체를 매번 다시 작성하지 말고 필요한 부분만 수정한다.
- 구현 후 동일한 검증을 반복하지 않는다.
- 진행 보고는 `확인 → 구현 → 검증 → 결과` 네 단계 이내로 짧게 한다.
- 최종 응답에는 변경 파일, 실행 명령, 검증 결과, 남은 문제만 기록한다.

## 8. 구현 순서

1. 관련 파일과 Python 버전을 확인한다.
2. 기존 구현이 있으면 요구사항과 비교한다.
3. `requirements.txt`를 최소 구성으로 작성한다.
4. `face_landmark.py`를 구현한다.
5. 구문 검사를 실행한다.
6. 입력 이미지가 있으면 프로그램을 실제 실행한다.
7. 결과 파일 생성 여부와 크기가 0보다 큰지 확인한다.
8. 가능한 경우 결과 이미지에서 얼굴 위 랜드마크가 표시됐는지 확인한다.
9. 오류가 발견되면 원인에 해당하는 부분만 수정하고 다시 검증한다.

## 9. 검증 명령

환경에 맞게 다음 명령을 사용한다.

```bash
python --version
python -m pip install -r requirements.txt
python -m py_compile face_landmark.py
python face_landmark.py face.jpg
```

Windows에서 `python` 명령이 없으면 `py`를 사용한다.

```powershell
py -m pip install -r requirements.txt
py -m py_compile face_landmark.py
py face_landmark.py face.jpg
```

## 10. 완료 기준

다음을 모두 만족해야 완료로 보고한다.

- 프로그램이 구문 오류 없이 실행된다.
- 얼굴이 있는 정상 이미지에서 얼굴을 검출한다.
- 랜드마크 점, 연결선, 번호가 결과 이미지에 표시된다.
- 결과 파일이 생성되고 크기가 0보다 크다.
- 입력 오류와 얼굴 미검출 상황이 사용자 친화적으로 처리된다.
- 원본 이미지는 변경되지 않는다.
- README의 실행 명령과 실제 프로그램 사용법이 일치한다.
